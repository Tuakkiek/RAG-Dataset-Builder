## Introduction

Stochastic Shortest Path (SSP) problem: an MDP problem $P = ( \Sigma ,   s _ { 0 } ,   S _ { g } )$ such that

▸ there is at least one safe solution

▸ cost $( s , a , s ^ { \prime } )$ is always $> 0$

• Let $V ^ { * } ( s ) =$ expected cost of an optimal safe solution

• Optimality principle (Bellman’s theorem)

![](images/page_1_image_6.jpg)

$V^{*}(s) = \int_{0}^{s} \mathrm{if} s \mathrm{isa goal} \\ \min_{a \in \mathrm{Appendix}(s)} \sum_{s' \in \gamma(s,a)} \Pr(s' \mid s, a) \left[ \cos(s, a, s') + V^{*}(s') \right]$ , otherwise

• We’ll only consider safe $\mathrm { S S P ^ { \circ } s }$

▸ no dead-end states

Safe solution: $\operatorname* { P r } \left( S _ { g }   \mid   s _ { 0 } , \pi \right) = 1$

## Planning and Acting

Run-Lookahead $( \Sigma ,   s _ { 0 } ,   S _ { g } )$

<div class="docvortex-algorithm" style="white-space: pre-wrap; font-family:monospace;">
$s \leftarrow s_0$
while $s \notin S_g$ and Applicable($s$) $\neq \emptyset$ do
    $a \leftarrow Lookahead(\Sigma, s, S_g)$
    if $a =$ failure then return failure
    perform action $a$
    $s \leftarrow$ observe resulting state
</div>

As in Chapter 2, Lookahead can be modified to cut off its search before reaching $S _ { g }$

## Cost to Go

● Let π be a safe solution that’s defined at all non-goal states

▸ $\operatorname* { P r } \left( S _ { g }   \mid   s _ { 0 } , \pi \right) = 1$

▸ $D o m a i n ( \pi ) = S \setminus S _ { g }$

● Compute $V ^ { \pi }$ as |S| equations, $| S |$ unknowns

● Cost-to-go:

▸ expected cost at s if we first use $a _ { \flat }$ then use π afterward

$$
Q ^ {\pi} (s, a) = \sum_ {s ^ {\prime} \in \gamma (s, a ^ {\prime})} \Pr \left(s ^ {\prime} \mid s, a ^ {\prime}\right) \left[ \mathrm{cost} (s, a, s ^ {\prime}) + V ^ {\pi} (s ^ {\prime}) \right]
$$

● For every $s \in S \setminus S _ { g }$

▸ $\{ a ^ { \prime }   |   a ^ { \prime } { \in } \mathrm { A p p l i c a b l e ( s ) } \}$ includes $\pi ( s )$

▸ so $\{ Q ^ { \pi } ( s , a ^ { \prime } ) \mid a ^ { \prime } \in \mathrm { A p p l i c a b l e ( s ) } \}$ includes $\bar { V } ^ { \pi } ( s )$

▸ so min $\{ Q ^ { \pi } ( s , a ^ { \prime } ) \mid a ^ { \prime } { \in } \mathrm { A p p l i c a b l e } ( s ) \} \leq V ^ { \pi } ( s )$

▸ so let $\pi ^ { \prime } ( s ) \in \operatorname { a r g m i n } _ { a ^ { \prime } \in \mathrm { A p p l i c a b l e } ( s ) } Q ^ { \pi } ( s , a ^ { \prime } )$

## Policy Iteration

**until** π stops changing **do** compute $\{ V ^ { \pi } ( s ) \mid s \in S \}$ for each $s \in S \setminus S _ { g }$ **do** ● Converges in a finite number of iterations

[cost of using a then π]

Bellman-Update(s)

Q (s, a) \leftarrow \sum_ {s ^ {\prime} \in \gamma (s, a)} \Pr \left(s ^ {\prime} | s, a\right) \left[ \operatorname{cost} (s, a, s ^ {\prime}) + V (s ^ {\prime}) \right]

V (s) \leftarrow \min _ {a} Q (s, a)
$$

## Value Iteration

● $V _ { 0 } ;$ a heuristic function

• e.g., adapt an h heuristic from Chapter 2

▸ $V _ { 0 } ( s ) =$ estimated cost of getting from s to $S _ { g }$

▸ Require $V _ { 0 } ( s ) = 0$ for every $s \in S _ { g }$

● V and π are global arrays

● Initially $V ( s ) = V _ { 0 } ( s ) \; \nabla$ s

● In each iteration, $V \leftarrow$ improved estimate

● approximate fixed point: V stops changing very much

▸ usually when the residual (max change to $V ) \mathbf { \dot { \varepsilon } } \mathrm { i s } \leq \eta$

▸ The book gives several other possibilities

● V doesn’t depend on π

Could wait and compute π at the very end

## Discussion

• In each iteration of Policy Iteration

▸ Compute $V ^ { \pi }$ for current π

• |S| linear equations, |S| unknowns

▸ Use $V ^ { \pi }$ to choose new π

• argmin $Q ^ { \pi } ( s , a )$ at each state

• More work per iteration than value iteration

▸ Needs to solve simultaneous equations

• In each iteration of Value Iteration

▸ Compute new $V ;$ min $\mathcal { Q } ( s , a )$ at each state

▸ New V is a revised set of heuristic estimates

• Doesn’t depend on any π

▸ new π = argmin $\mathcal { Q } ( s , a )$ at each state

• But $V \neq V ^ { \pi }$

▸ Less work per iteration: doesn’t need to solve a set of equations

• More iterations to converge unless $V _ { 0 }$ is good

● At each iteration, both algorithms need to examine the entire state space

▸ Number of iterations polynomial in |S|, but |S| may be quite large

● Next: use search techniques to avoid searching the entire space

## Heuristics through Determinization

What to use for $V _ { 0 } ( s ) ?$

One possibility: a heuristic for the determinized domain $\Sigma _ { d }$

For each action a of Σ

▸ If a has k possible outcomes, then

• $\Sigma _ { d }$ contains k deterministic actions $a _ { 1 } , . . . , a _ { k }$

• one for each of $a ^ { \flat } \mathbf { S }$ outcome

● Let h be a classical heuristic function for $\Sigma _ { d }$

If h is admissible for $\Sigma _ { d }$ then also admissible for Σ

● Proof:

▸ Let $\pi ^ { * }$ be any optimal solution for $( \Sigma , s , g )$

Then $V ^ { * } ( s ) = E ( \cos ( \pi ^ { * } ) )$ = weighted avg. of all executions of $\pi ^ { * }$

▸ Let $p ^ { * }$ be the least costly execution of $\pi ^ { * }$

• $p ^ { * }$ is a solution for $( \Sigma _ { d } , s , g )$

• so $h ( s ) \leq \operatorname { c o s t } ( p ^ { * } ) \leq E ( \operatorname { c o s t } ( \pi ) )$

## Heuristics through Determinization

What to use for $V _ { 0 } ( s ) ?$

Another possibility: call a classical planner on the determinized problem $( \Sigma _ { d } , s , g )$

• Get plan $p = \langle a _ { 1 } , a _ { 2 } , . . . , a _ { n } \rangle$

• Return $V _ { 0 } ( s ) = \cos ( p )$

**Theorem.** If the classical planner always returns optimal solutions, then $V _ { 0 }$ is admissible

Outline of proof:

▸ Let $\pi ^ { * }$ be any optimal solution for $( \Sigma ,   s ,   g )$

▸ Then $V ^ { * } ( s ) = E ( \cos ( \pi ^ { * } ) )$ = weighted avg. of all executions of π

▸ Let $p ^ { * }$ be the least costly execution of π

• $p ^ { * }$ is a solution for $( \Sigma _ { d } , s , g )$ , so the classical planner returns a plan p of ≤ cost

• So $V _ { 0 } ( s ) = \operatorname { c o s t } ( p ) \leq \operatorname { c o s t } ( p ^ { * } ) \leq E ( \operatorname { c o s t } ( \pi ) )$

## Digression: Monte Carlo rollouts

● Multi-arm bandit problem: statistical model of sequential experiments

▸ Name derived from one-armed bandit (slot machine)

● Multiple actions $a_{1}, a_{2}, \ldots, a_{n}, \mathrm{e.g.}, a_{n} = \mathrm{p l a y}$ machine i

● Each $a _ { i }$ provides a reward from an unknown probability distribution $p _ { i }$

▸ Assume every $p _ { i }$ is stationary

• same every time, regardless of history (not true for real slot machines)

▸ Objective: maximize expected utility of a sequence of actions

● Exploitation vs exploration dilemma:

▸ Exploitation: choose an action that has given you high rewards in the past

▸ Exploration: choose a less-familiar action in hopes that it might produce a higher reward

![](images/page_40_image_11.jpg)

Credit: [Billy Hicks](https://en.wikipedia.org/wiki/User:BillyH), [CC BY-SA 4.0](https://en.wikipedia.org/wiki/Wikipedia:Text_of_the_Creative_Commons_Attribution-ShareAlike_4.0_International_License)

## UCB (Upper Confidence Bound) Algorithm

● Assume all rewards are between 0 and 1

▸ If they aren’t, normalize them

● For each action $a ,$ let

▸ r(a) = average reward you’ve gotten from a

▸ n(a) = number of times you’ve tried a

▸ $\begin{array} { r } { t = \sum _ { a } n ( a ) } \end{array}$

▸ $Q(a)=r(a)+\sqrt{2(\ln t)}/n(a)$

<div class="docvortex-algorithm" style="white-space: pre-wrap; font-family:monospace;">
UCB algorithm
    if there are any untried actions:
        $\tilde{a} \leftarrow$ any untried action
    else: $\tilde{a} \leftarrow \arg\max_a Q(a)$
    perform $\tilde{a}$ and get reward
    update $r(\tilde{a}), n(\tilde{a}), t, Q(\tilde{a})$
</div>

● Theorem (given some assumptions):

As $t \to \infty ,   \operatorname { a r g m a x } _ { \tilde { a } \in \mathcal { A } } Q ( a )$ → optimal choice

## UCT Algorithm

● Recursive UCB computation on an SSP

▸ Adapted for minimization rather than maximization

● Monte Carlo rollout:

▸ At s, choose action ã using UCB computation

• Perform ã, get state s′

• Do the same thing recursively at $s ^ { \prime }$

• Continue until reaching a goal, dead end, or depth h

▸ At each state visited, keep statistics on choices, utilities

![](images/page_44_image_9.jpg)

UCB:

if there are untried actions: $\tilde { a } \leftarrow$ any untried action else: $\tilde { a } \gets \operatorname { a r g m a x } _ { a } Q ( a )$ perform ã and get reward update r(ã), n(ã), t , Q(ã)

● Statistics for each action a:

▸ r(a) = average reward

▸ n(a) = number of times you’ve tried a

▸ $\begin{array} { r } { t = \sum _ { a } n ( a ) } \end{array}$

▸ $Q(a)=r(a)+\sqrt{2(\ln t)}/n(a)$
